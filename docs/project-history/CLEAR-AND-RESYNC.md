# Clear the table and read it again

On the linked table, under **Table menu → Clear board & resync**, there is a command to completely clear the virtual table. After confirmation, all loose parts are returned to stock. Tile settings, temporary scan registrations and unconfirmed movements are cleared. The official Android save and the Core connection will not be adjusted. Any active sensor contacts are only released; no scan, move, or roll is sent.

The private adapter saves a local recovery copy of the table and tile settings before emptying. The reset is saved and other open board pages adopt it via the existing status poll. Even if the new session receives the same revision as the previous one, the recovery generation forces a re-read. Tile revisions keep accumulating so that an old browser operation is rejected.

The background adapter then starts over with two matching observations. Show the component setup screen in Milan to rebuild influence and control in all thirty districts. A complete, stably recognized component setup also automatically starts with an empty table: components from a previous campaign are not left behind. Repeated images within the same setup step do not erase newly added components.

This is not a full save import. The official app does not provide a complete board snapshot message via this link. Only visible and supported map data or instructions are automatically adopted. Characters should be rescanned and placed as necessary; location bonuses, hidden data, and story markers require their own setup steps. Thus, clearing on any game screen cannot immediately reconstruct all components. The interface mentions that restriction before emptying.

A visible **Next Encounter in…** notification can now also restore the associated [investigation token](../games/milan-uprising/INVESTIGATION-MARKER-SYNC.md). Without such supported instruction, research positions will not be recovered from old campaigns.

Addition on October 25: the [regular city map can now also restore positively recognized control tokens and visible research icons](../games/milan-uprising/MAP-RECOVERY.md). Fully readable character portraits can fill in missing positions; stacked or hidden parts remain incomplete. Show the city map after a reset and leave it open for the additional image reading.

Verification: The headless tests check tile reset and rejection of old revisions. The LAN test checks authentication, origination, and forwarding of the reset. An isolated private adapter trial checks an empty saved table, recovery copy, sensor release only, re-reading a recorded Android setup, and retention of new markers within the same step. A browser trial checks cancel and confirm via the table menu without any actual game input. This does not replace a live acceptance test in a full campaign.
