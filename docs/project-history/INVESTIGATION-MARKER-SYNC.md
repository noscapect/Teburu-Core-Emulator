# Research token from an encounter report

The private adapter recognizes the visible message **[location] – Next Encounter in [destination]** in a phase overview. Both location names must be well-known city districts. After two matching observations, a token with the side **Investigation** is placed at the destination. An existing Investigation token is reused; rereading does not create duplicates. Other Investigation tokens and Restricted sides are retained.

This also restores a missing token after **Clear board & resync**, as long as the message in question is still visible in Milan. The takeover works in the background without an open browser or Codex. An unknown destination, unclear message or empty token stock does not partially change the table. This extension does not read research icons from arbitrary map screens: without a visible supported instruction, the adapter cannot yet reconstruct that information.

The current notification **QT8 – Next Encounter in Washington** has been checked against the visible marker at Washington in the official Android app. After activation, the background adapter placed this token; the shared board page shows it near Washington with the local Investigation artwork. No sensor contact or game action was sent to Milan.
